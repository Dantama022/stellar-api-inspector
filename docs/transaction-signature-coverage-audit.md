# Transaction Signature Coverage Audit

`stellar-api-inspector signature-coverage-audit <envelopeXdr> --network testnet --horizon https://horizon-testnet.stellar.org --signer G...`

The audit decodes a base64 `TransactionEnvelope` XDR, reports its transaction and operation sources, verifies signatures against the selected network passphrase, then separately compares verified signer identities and weights with current Horizon account signer configurations and thresholds. Supply additional public keys with repeatable `--signer` options to verify signatures whose keys are not account signers; those keys never contribute authorization weight unless Horizon lists them as signers. A fee-bump transaction checks its fee source's low threshold using outer signatures, separately from inner transaction signatures. JSON is available with `--json`; `--output <path>` saves either formatted or JSON output.

Supported classic operation thresholds: low for allow trust and bump sequence; medium for account creation, payments and path payments, offers, change trust, and manage data; high for account merge. For each account, the highest required threshold across its transaction and operation roles is evaluated. Operation rules not listed here, including parameter-dependent `setOptions`, are inconclusive. Valid Ed25519 signatures matching an on-chain signer contribute that signer's weight once. Ed25519 transaction extra signers are checked independently.

Unknown operation authorization rules, Soroban authorization, non-Ed25519 signer types, missing account data, and unresolvable signature identities are reported as incomplete or inconclusive; they are never treated as proof of readiness. Invalid signatures are reported independently from threshold weight. Horizon data is a point-in-time snapshot. Sequence constraints, time bounds, fees, balances, operation validity, and ledger execution are not assessed. The command is read-only and never signs, submits, or modifies a transaction.
